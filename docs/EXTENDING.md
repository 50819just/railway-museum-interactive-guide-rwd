# 如何依照 AGENTS.md 延伸網站

這份指南提供依現有程式整理的可重複使用流程。B 節的參觀準備頁面已有實作；其他範例不因此視為完成。範例的站數、字數、頁面與檔名是起點，不是產品上限；需求改動時按 AGENTS.md 第 0 節同步調整程式、資料相容性、測試與文件。

## A. 更新一個站點的文化導讀

適合只調整內容、不改變站數與玩法的任務。

1. 先讀根目錄 AGENTS.md、docs/UI_COPY_PREFERENCES.md、tests/stationCulture.test.mjs 與 tests/i18n.test.mjs。
2. 以 src/data/stations.js 確認既有站點 ID，不修改 ID、座標或順序。
3. 這個範例只改內容，因此沿用目前兩段與字數檢查；若任務另有結構需求，不必硬塞進舊格式，先盤點消費端與測試後一起調整。查核本次文字使用的來源。編修 src/features/explore/stationCulture.js，維持兩段摘要／詮釋、觀察提示與來源欄位；不要直接複製來源長文。
4. 欄位範本如下；尖括號是填寫說明，不可原樣發布：

```js
// stationCulture 中的既有 ID：
'1': {
  title: '<導讀標題>',
  paragraphs: ['<40–75 字事實摘要>', '<40–75 字延伸詮釋>'],
  observation: '<至少 20 字、安全且限開放區域的觀察提示>',
  sources: ['<cultureSources 內存在的鍵>'],
  guideLabel: '展場文化導讀',
  sourceScope: '<超過 15 字的來源涵蓋範圍>',
  status: '開放範圍依館方當日公告；集片點未經館方確認。',
  contentType: '第一段為官方資料摘要；第二段為延伸文化詮釋，非館方展文。',
}
```

5. 更新相關翻譯。依既有 localize/字串對照機制處理，移除舊對照前先查其他引用，不更動問題或旅程資料。
6. 執行 `node --test tests/stationCulture.test.mjs tests/i18n.test.mjs`，再執行 AGENTS.md 的完整檢查。
7. 實際開啟該站導讀，確認兩段內容、觀察提示、來源入口與四語顯示。不能只用資料測試宣稱畫面通過。

可交給 AI 的指令：

> 請先讀 AGENTS.md 與 docs/EXTENDING.md。只更新第 1 站文化導讀，依我提供且可查核的資料改寫，維持現有兩段格式與來源資訊，同步四語與測試。不更動站點 ID、站數、答題、獎勵、付款或樣式。不自行發布。請回報修改與驗證結果；缺資料時不要補造。

## B. 新增頁面的流程：以「參觀準備」為例

此流程已套用於 `#visit`：依 AGENTS.md 建立頁面、接上公開入口與四語，加入準備清單與觀察籤。下表也可用來延伸其他頁面；開始前先確認目標頁面是否已存在，避免重複建立。

| 步驟 | 修改位置與要求 |
| --- | --- |
| 建立功能 | src/features/visit/VisitPage.jsx、VisitPage.css；只放一般準備事項，不猜測即時營業資訊 |
| 沿用樣式 | 使用既有標題、卡片、token；class 採 visit- 前綴 |
| 頁面註冊 | 在 src/App.jsx 接入 #visit、lazy 載入與渲染 |
| 訪客範圍 | 頁面若全為公開資訊，明確納入 App.jsx 訪客可用名單；不得放私人資料 |
| 放置入口 | 在 src/features/more/MorePage.jsx 新增入口；必要時更新 AppShell.jsx 頁面名稱，不增加底部主要分頁 |
| 多語 | 沿用 src/i18n/ 與 t(key)，新增繁中、英文、日文、韓文 |
| 測試 | 新增 tests/visitPage.test.mjs；檢查路由、訪客政策、入口、翻譯；另實際檢查畫面與鍵盤 |
| 驗收 | 直接開 #visit、重新整理、返回、訪客／會員、四語、320／390／768／1440px，確認舊功能仍可用 |

可交給 AI 的指令：

> 請依 AGENTS.md 與 docs/EXTENDING.md 的 B 流程新增一個公開資訊頁面。先檢查是否已有相同功能，再依我提供的主題與內容建立；參考 #visit 的元件、樣式、四語與測試。不改底部四項導覽、不動旅程資料與付款。缺少主題或內容先釐清，不捏造；未授權不提交、推送或發布。

## C. 擴充完成紀錄

每次實際執行後，記錄：

- 任務與日期。
- 使用的規則段落。
- 修改檔案及保留不動的範圍。
- 測試指令與結果、瀏覽器檢查結果。
- 尚未驗證或需使用者確認的項目。

若沒有實際執行擴充，只能寫「已提供擴充模板」，不可寫「新增頁面已完成」。

## D. 規則本身需要調整時

1. 指出哪一條是目前慣例、為什麼不再符合新需求。
2. 列出真正受影響的程式、資料、翻譯與測試；一般修改不擴張成全站重構。
3. 保留安全與來源底線。涉及舊資料時規劃相容／遷移；已授權的一般調整不反覆請示。
4. 一起更新文件與測試，說明舊行為、新行為及未驗證項；不只刪除失敗測試。

例如「導讀需要三段」不是拒絕任務的理由。應先確認呈現元件是否可渲染三段、翻譯是否覆蓋，以及原本兩段斷言如何改成有意義的新驗收。此例僅說明處理方式，沒有在本次改變導讀內容或既有測試。

## E. 已實作的延伸案例：參觀準備與觀察籤

- 頁面：src/features/visit/VisitPage.jsx，樣式：VisitPage.css。
- 資料與純邏輯：visitModel.js；四語文字：visitCopy.js，合併至既有 src/i18n/ 字典，不建立另一套語言狀態。
- 路由：App.jsx 的 #visit；入口：AppShell 公開選單與 MorePage 服務清單；保留原四個主要分頁。
- 互動：三項勾選即時回饋、四種可替換觀察籤，避免連續抽到相同任務。只用頁面記憶體，不讀寫旅程、訂單、拼圖、獎勵或照片。
- 權限：訪客可閱讀與操作；訪客不顯示導向私人服務頁面的次要返回入口，仍可返回探索。
- 新增觀察籤：在 observationTasks 加入唯一 id、既有 Icon 名稱與 titleKey/bodyKey，在四語文字新增對應欄位；呈現元件與抽籤邏輯不需複製。新增檢查項目亦遵循資料與四語一起更新。
- 自動驗證：node --test tests/visitPage.test.mjs tests/i18n.test.mjs；包含選題邊界、無立即重複、資料可擴充性、四語一致、入口與資料隔離。涉及 UI 的修改仍須另行瀏覽器檢查。

這是產品開發案例，不代表現場人流、真機相機或正式付款已驗證。上線狀態以實際部署為準。
