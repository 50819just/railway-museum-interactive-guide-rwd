# VibeCode 規格與協作文件區

本區保留產品規格、初期範本與開發紀錄。部分文件仍是早期快照，不能將其中的「起始頁」「待填」或當時授權範圍當作目前網站狀態或永久限制。

## 有效入口

1. [根目錄 README](../README.md)：目前功能、目錄、環境及部署方式。
2. [AGENTS.md](../AGENTS.md)：AI 開發規則、資料保護與需求變更方式。
3. [system.md](system.md)：規格區的協作補充，與根目錄規則保持一致。
4. [SPEC.md](SPEC.md)：現有架構與產品範圍索引。
5. [擴充指南](../docs/EXTENDING.md)：內容、頁面與規則調整的操作範例。

## 如何使用本區

- 只閱讀本次任務相關文件，不要求每次修改前填完整個規格庫。
- 現有程式是目前行為證據；最新需求定義目標，不把 bug 當成需求。
- 過時文件可在任務範圍內更新。若矛盾影響資料安全、產品方向或授權範圍，再先釐清。
- 規格編號與表格是協作工具，可按需要採用，不是開發的強制前置門檻。
- 舊驗證紀錄只證明當時檢查，不代表現在版本已通過。
- 新增文件應標明目的、適用範圍與依據；不要大量複製相同規則，避免多個入口互相衝突。
- 外部資料的內容、日期、來源與權限保留可追溯性，不捏造館方合作、授權或成效。
- 規格、測試與實作要一起隨需求演進，不為符合舊範本而拒絕合理修改。
